1. Executive Summary & Investigation Context

Scenario: Handed a web application built using AI-assisted ("vibe coding") techniques that users reported as "feeling broken". Our objective was to thoroughly exercise the core user journeys (Sign-up, Authentication, Content Creation, Markdown Editor, Edit Article, Delete Article, Profile Settings, and Logout), identify high-impact functional, architectural, security, and UX defects, and present a rigorous Root Cause Analysis (RCA) with production remediation steps.

AI-assisted vibe-coded applications often achieve visually compelling mockups rapidly but frequently omit defensive programming paradigms: asynchronous state management synchronization, reactive form cleanup, destructive action confirmation guards, secure session handling, and accessibility attributes. During this audit, 6 distinct issues were identified, documented, and classified.

3. In-Depth Root-Cause Analysis (Issue #1: Disappearing Navigation Header)

1. What is Happening?

When an authenticated user navigates between routes inside the Single Page Application (e.g. from the home feed to the article editor, an existing article, or the user profile page), the top navigation header abruptly loses its authenticated elements ("Home", "New Article", "Settings", and user profile avatar), rendering only the raw brand link "conduit". The user is left in a broken visual state with no access to core navigation links until they execute a full browser hard refresh.

2. Why is it Happening?

This defect is caused by an architectural desynchronization between Angular's reactive authentication state and the component router lifecycle. The HeaderComponent binds its navigation elements via an *ngIf="currentUser" directive backed by a local property populated through a manual subscription to UserService.currentUser$. When internal client-side navigation occurs, child routes trigger without invoking the root application bootstrap sequence. Because the underlying observable in UserService was implemented as a cold or un-replayed subject rather than a multicasted replay stream, late-subscribing or re-rendering components fail to receive the cached user session object. Consequently, the user object evaluates to undefined/null, and the template removes the navigation elements from the DOM.

3. How Would You Fix It? (Production Remediation)

To resolve this permanently and build resilience into the application, implement the following four-phase fix:

  • Replay Authentication State: In UserService, ensure the currentUser$ stream uses a BehaviorSubject or is piped through shareReplay({ bufferSize: 1, refCount: false }). This guarantees that any component subscribing at any point in the router lifecycle immediately receives the current user object:
    // user.service.ts private currentUserSubject = new BehaviorSubject<User | null>(this.getStoredUser()); public currentUser$ = this.currentUserSubject.asObservable().pipe(distinctUntilChanged(), shareReplay(1));
  • Use Declarative Async Pipe in Header Template: Eliminate manual subscription management inside HeaderComponent and leverage Angular's async pipe, which automatically handles subscription lifecycles, change detection, and template unwrapping:
    <!-- header.component.html --> <ng-container *ngIf="currentUser$ | async as user; else guestNav"> <ul class="nav navbar-nav pull-xs-right"> <li class="nav-item"><a class="nav-link" routerLink="/">Home</a></li> <li class="nav-item"><a class="nav-link" routerLink="/editor">New Article</a></li> <li class="nav-item"><a class="nav-link" routerLink="/settings">Settings</a></li> <li class="nav-item"><a class="nav-link" [routerLink]="['/profile', user.username]">{ user.username }</a></li> </ul> </ng-container>
  • Implement Route Session Resolver: Add an Angular UserResolver to protected and dependent routes to verify session validity and pre-fetch the authenticated user profile before routing completes.
  • Automated Regression Suite: Add automated Playwright end-to-end tests verifying navbar state persistence across sequential route hops (/ → /editor → /article/:slug → /settings → /profile).
